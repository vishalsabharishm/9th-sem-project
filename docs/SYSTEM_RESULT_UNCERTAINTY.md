# System result and its uncertainty

**The reference for which numbers go in the paper, and what may be claimed
about them.**

Added in Step 5. Generated by `tools/sliding_window_uncertainty.py`, which
reads committed artifacts only — no checkpoint, no dataset, no network.

---

## 1. Three results exist. Only one is the system.

They must never be quoted interchangeably or averaged together.

| | Experiment 1 | Clean baseline | **Sliding-window system** |
|---|---|---|---|
| Checkpoint | `notebook5d98537e15` v2 | `notebook7bb9a86555` v3 | **same as clean baseline** |
| Regime | whole-clip, 1 pass | whole-clip, 1 pass | **17 windows, `max ≥ 0.14`** |
| Threshold | 0.5 (also 0.14, biased) | 0.16 | **0.14 on max-of-windows** |
| Protocol | monitored on the reporting set | carved validation | carved validation |
| Accuracy | 0.8604 | 0.8325 | **0.7893** |
| Status | **superseded, biased** | model-only upper bound | **what the system does** |
| Per-clip data | available | **not recovered** | available |
| Recomputable here | yes | no (point estimate only) | **yes, exactly** |

The sliding-window row is the one that describes the running system. The clean
baseline is the same model's ceiling if it were allowed to see the whole clip
at once, which the streaming design does not permit.

## 2. The sliding-window result is exactly recomputable

`temporal_risk/primary_window_scores.csv` + `temporal_risk/frozen_aggregation.json`
reproduce the recorded confusion matrix **exactly**, with no checkpoint:

```
recomputed  TP=160  FP=43  TN=151  FN=40   accuracy 0.7893401015228426
recorded    TP=160  FP=43  TN=151  FN=40   accuracy 0.7893401015228426
difference  0.0
```

`tools/sliding_window_uncertainty.py` asserts this before computing anything and
refuses to report intervals around a point estimate it cannot reproduce.

The per-clip continuous score for this regime is **`max` over the 17 window
probabilities** — precisely the quantity the frozen rule thresholds. 393 of 394
clips have a distinct value.

## 3. Clip-level 95% intervals

n = 394 (200 Fight, 194 NonFight). Method as established in Step 4: Wilson score
intervals for proportions, seeded percentile bootstrap for everything else,
nothing for what neither supports.

### Tier 1 — Wilson, denominator fixed by the split

| Metric | Point | 95% CI | Counts | Width |
|---|---:|---|---:|---:|
| **accuracy** | **0.7893** | **[0.7464, 0.8267]** | 311/394 | 8.03 pp |
| recall | 0.8000 | [0.7391, 0.8495] | 160/200 | 11.04 pp |
| specificity | 0.7784 | [0.7148, 0.8311] | 151/194 | 11.63 pp |
| prevalence (Fight) | 0.5076 | [0.4584, 0.5567] | 200/394 | 9.83 pp |

### Tier 2 — Wilson, conditional on a model-chosen denominator

| Metric | Point | 95% CI | Counts | Width |
|---|---:|---|---:|---:|
| precision (PPV) | 0.7882 | [0.7269, 0.8388] | 160/203 | 11.19 pp |
| NPV | 0.7906 | [0.7274, 0.8423] | 151/191 | 11.48 pp |

The denominator is the number of clips the system *chose* to alarm on (203), not
a design constant. The interval is conditional on that count.

### Tier 3 — percentile bootstrap, not binomial proportions

10,000 resamples, seed 42, stratified by class.

| Metric | Point | 95% CI |
|---|---:|---|
| F1 | 0.7940 | [0.7525, 0.8333] |
| ROC-AUC † | 0.8837 | [0.8505, 0.9140] |
| PR-AUC † | 0.8943 | [0.8641, 0.9225] |

† **These rank the max-of-17-windows score.** They describe this regime and are
**not comparable** with the clean baseline's whole-clip ROC-AUC 0.9251, which
ranks a different quantity. Quoting them side by side as if they measured the
same thing would be wrong.

No Wilson interval is claimed for F1 or either AUC — none is a count out of a
denominator.

## 4. Source-video dependence — clip-level intervals are too narrow

The 394 clips come from **174 inferred source videos** (mean 2.26 clips each,
largest 13). Clips cut from one video share camera, scene and subjects, so their
outcomes are correlated and the effective sample size is below 394.

Unlike Experiment 1's `predictions.csv` — which carries only a row index and
forced a positional-alignment inference in Step 4 — the sliding-window scores
**carry clip names**, so grouping is applied directly here.

| Metric | Clip-level | Source-video-level | Widening |
|---|---|---|---:|
| accuracy | [0.7487, 0.8299] 8.12 pp | [0.7327, 0.8421] 10.94 pp | **1.35×** |
| F1 | [0.7525, 0.8333] 8.08 pp | [0.7210, 0.8512] 13.02 pp | **1.61×** |
| ROC-AUC | [0.8505, 0.9140] 6.35 pp | [0.8359, 0.9261] 9.02 pp | **1.42×** |
| PR-AUC | [0.8641, 0.9225] 5.84 pp | [0.8370, 0.9354] 9.84 pp | **1.68×** |

**Report the source-video-level interval, or the clip-level one with this
limitation stated.** Clip-level alone overstates precision by 35–68%.

### The grouping is inferred, not proven

It comes from the `<source_id>_<index>.avi` filename convention, which matches
all 394 primary and all 240 carve clips.
`rwf2000_config.SplitPolicy.validation_grouped_by_source_video` shows the
dataset authors treated source video as a real grouping — supporting evidence,
not proof. This repository holds **no per-clip source-video record**. Two
unrelated videos sharing an id prefix would be merged; one video released under
two ids would be split. State this whenever the clustered interval is quoted.

## 5. Clean baseline — point estimate and Wilson intervals only

Its per-clip predictions were **never recovered** from Kaggle notebook
`7bb9a86555` v3; only aggregate metrics and the confusion matrix
(TP 182 / FP 48 / TN 146 / FN 18) were transcribed.

The counts are the sufficient statistics for these proportions, so Wilson
intervals from them are a computation, not an invention:

| Metric | Point | 95% CI | Counts |
|---|---:|---|---:|
| accuracy | 0.8325 | [0.7924, 0.8661] | 328/394 |
| recall | 0.9100 | [0.8622, 0.9423] | 182/200 |
| specificity | 0.7526 | [0.6873, 0.8080] | 146/194 |
| precision (PPV) | 0.7913 | [0.7342, 0.8388] | 182/230 |
| NPV | 0.8902 | [0.8332, 0.9294] | 146/164 |

**Not available, and not approximated:**

- any bootstrap interval (F1, ROC-AUC, PR-AUC) — needs per-clip scores;
- the source-video clustering correction — needs to know which clip each
  prediction belongs to. The Wilson intervals above are therefore
  **uncorrected and anti-conservative**, and unlike the sliding-window result
  the size of that effect **cannot be measured**.

## 6. Time to alarm — censoring handled explicitly

200 Fight clips: **160 alarm, 40 never do**. Censoring is *administrative and
identical* — every non-detection is censored at 4.800 s, the end of the last
complete window. No clip leaves the risk set early.

Because all censoring occurs after the 80th percentile, every quantile at or
below the detected fraction (0.800) is **exact, not estimated**. No
Kaplan-Meier estimation is required and none is claimed.

### Two different quantities — do not conflate them

| | Over **all 200** Fight clips | Conditional on the **160** detected |
|---|---:|---:|
| q25 | 0.533 s | — |
| **median** | **0.800 s** | **0.533 s** |
| q75 | **3.733 s** | **1.600 s** |
| q80 | 4.800 s | — |
| mean | *not defined under censoring* | 1.272 s |

The conditional median answers *"when the system catches a fight, how fast?"*
The unconditional median answers *"how long until half of all fights are
caught?"* **Step 2 reported the conditional figures.** The unconditional p75 is
more than twice the conditional one.

Quantiles above 0.800 are **never reached** — those clips do not alarm at all.
No mean over all Fight clips is reported, because it does not exist without
imputing the censored clips.

**The 40 censored clips are never treated as 4.8-second alarms.** A test
constructs a case where that imputation would visibly change the answer and
asserts the honest path returns "not reached" instead.

### Uncertainty for the unconditional median

Percentile bootstrap; a resample in which fewer than half the clips alarm has no
median below censoring and is discarded, never imputed.

| Level | Median | 95% CI |
|---|---:|---|
| clip-level | 0.800 s | [0.800, 1.333] |
| source-video-level | 0.800 s | [0.533, 1.867] |

Alarm times are discrete — one of 17 possible window end times — so the
bootstrap distribution is lumpy and the endpoints land on those values.

## 7. Can 0.7893 and 0.8325 be compared? **No formal test is supported.**

They are the **same checkpoint on the same 394 clips under two inference
regimes**, which is exactly the comparison worth making. It cannot be tested.

**Why McNemar is unavailable:** it needs each clip's outcome under *both*
regimes. The sliding-window per-clip outcomes are committed; the clean
baseline's are not. Without pairing there is no discordant-pair count and the
test is undefined.

**Why an unpaired two-proportion test is also refused:** the two samples are not
independent — they are the identical 394 clips scored twice. Such a test would
produce a p-value that means nothing.

**Why the available alternative was rejected:** Experiment 1's per-clip
predictions *are* available on the same 394 clips, but pairing against them
would confound two changes at once — a different checkpoint (`notebook5d98537e15`
v2) *and* a different regime — and its rows carry no clip identifier, so
positional alignment could not be verified either.

**What may be said:** both point estimates and their descriptive intervals, side
by side, noting same checkpoint / same clips / different regime. Nothing about
significance. Note also that the two accuracy intervals overlap
([0.7464, 0.8267] vs [0.7924, 0.8661]) — and that overlap is *not* evidence of
no difference, any more than non-overlap would be evidence of one, for paired
data.

**What would unblock it:** the clean baseline's `predictions.csv` from
`clean_experiment/final_evaluation/`. With it, McNemar's exact test on 394
paired outcomes becomes available.
