How Sentinel Vision works

Detection

YOLOv8s person detection on every decoded frame, at the same confidence the research pipeline used.

Tracking

Identities maintained across frames, with retained-but-unmatched tracks filtered out before any rule sees them.

Spatial Analysis

Stationarity, proximity, crowding and restricted-area rules, plus a measured motion feature. Undefined stays undefined.

Temporal Analysis

R3D-18 scores overlapping 16-frame windows at stride 8; a frozen rule aggregates them into one clip decision.

Evidence Fusion

A configured layer combining temporal and spatial evidence under thresholds read from the frozen protocol.

Explainability

Gradient-based temporal saliency for a chosen window — a localisation diagnostic, not a causal explanation.

Temporal window timeline (16-frame windows, stride 8)

The temporal branch does not score the clip as a whole: it scores overlapping 16-frame windows and takes the maximum. Each point is one scored window; the segments between them only help the eye travel, and are not probabilities the model produced. Click a window to select it for saliency. In REPLAY mode these probabilities are replayed from the committed scores; in LIVE MODEL mode each one was produced by an R3D-18 forward pass during that run. Clicking a window does not run the model.

Evidence fusion

A configured fusion layer combining the temporal probability with an interpretable spatial motion feature. The spatial feature is a whole-video aggregate, so the fusion decision is available only after the whole video has been processed — it is not a causal mid-video alarm. Thresholds are read from the frozen protocol, not tuned here.

In the frozen confirmatory evaluation, fusion did not produce a statistically significant improvement over the temporal-only baseline (exact McNemar p = 0.771). The temporal-only rule remains the system's decision. Fusion is shown because the research question concerns an explainable multi-signal system, not because it performs better.

Explainability

Gradient-based temporal saliency for one completed window.

1 · Select a temporal window

Only windows this run actually scored are offered, so a selected window can always be reconstructed from source frames.

2 · Generate saliency

Saliency is computed on demand for one completed 16-frame window, not for every frame: it needs a backward pass as well as a forward one (about 2.2 s per window on this CPU, measured). It is unavailable in the default replay path, which has a recorded probability but no model weights to differentiate.
